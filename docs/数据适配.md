# 卡片数据接入说明

> 卡片的数据来源是 x-hub 宿主桥 `xhub.data.todos.list()`（内置 SQLite 待办库）。
> 浏览器预览时的“模拟数据”由 `shared/mock-bridge.js` 在**同一个接口**后面提供，
> 所以卡片只认一份契约，不需要区分真假后端。

---

## 1. 数据链路

```
xhub.data.todos.list()         宿主桥（真实待办）
        │
        ├─ module/data.js#fetchTodos()   取数 + 8s 超时 + 错误归一
        │        │
        │        └─ normalizeTodo()      宿主字段 → 卡片模型（类型/单位/缺字段兼容）
        │
        ├─ module/app.js#toCalcModels()  模型 → 倒计时计算字段（唯一一处字段映射）
        │
        └─ shared/countdown.js           days / status / 分组 / 统计
```

三层的职责边界：

| 层 | 负责 | 不负责 |
|---|---|---|
| `data.js` | 取数、超时、错误文案、字段归一、丢弃脏行 | 业务判断（逾期/临期） |
| `app.js` | 状态机、渲染、交互、字段名映射到计算层 | 网络与容错细节 |
| `countdown.js` | 纯日期计算与状态分档 | 任何 IO |

---

## 2. 字段映射

| 后端字段（宿主 `todos`） | 卡片模型 | 计算层字段 | 处理 |
|---|---|---|---|
| `id` | `id` | `id` | 缺失则**丢弃该行**并计入 `dropped` |
| `title` | `title` | `title` | 压缩连续空白；空/缺失 → `（未命名待办）` |
| `due_at` | `dueAt` | `due_at` | **秒级自动 ×1000**；≤0 / 非数字 / 超范围 → `null` |
| `done` | `done` | `done` | `0/1`、`"0"/"1"`、`"true"`、布尔都能识别 |
| `priority` | `priority` | `priority` | 字符串转数字，钳制到 `0..2` |
| `parent_id` | `parentId` | `parent_id` | 缺省 `null`；与父级合并由计算层处理 |
| `repeat_mode` | `repeatMode` | `repeat_mode` | 空/缺失 → `'once'` |
| `description` | `description` | `description` | `null` → 空串（卡片不展示，仅透传） |
| `completed_at` | `completedAt` | — | 卡片不使用，保留供后续过滤 |
| 其它字段 | 丢弃 | — | 后端加字段不影响卡片 |

响应包装容错：裸数组、`{ data: [] }`、`{ items: [] }`、`{ rows: [] }` 都能解析。

---

## 3. 因后端数据差异需要调整的字段

按影响面从大到小：

| # | 字段 | 差异 | 不处理会怎样 | 当前处理 |
|---|---|---|---|---|
| 1 | `due_at` | 秒级时间戳（外部导入/老数据） | 显示成 1970 年、全部逾期几万天 | `< 1e11` 视为秒并 ×1000 |
| 2 | `due_at` | 用 `''` / `0` / `"2026-11-06"` 表示空 | 出现「NaN 天」或错误逾期 | 统一判非法 → 未排期 |
| 3 | `done` | `true` / `1` / `"1"` / `"yes"` 混用 | 已完成项被算进逾期 | 统一布尔化 |
| 4 | `parent_id` | 可能缺失或为 `0` | 子待办重复计数 / 误折叠 | 只在 `!= null` 时参与折叠 |
| 5 | `priority` | 字符串或缺省 | 排序不稳定 | 转数字并钳制 `0..2` |
| 6 | `repeat_mode` | 空串 / `null` | 「周期」标签误显示 | 回落 `'once'` |
| 7 | `id` | 缺失或重复 | 渲染 key 冲突、提醒去重错乱 | 缺失丢弃；重复由上层数据保证 |
| 8 | `title` | 空串 / 只有空白 | 行高塌陷、点不到 | 占位标题 |
| 9 | 时区 | 后端存 UTC、前端按本地自然日算 | 差一天 | 统一按**本地日历日**计算（`due_at` 只当时间戳用） |
| 10 | 列表包装 | `{data:…}` / `{items:…}` | 读不到数据 | `unwrapList` 兼容三种包装 |

> 前端不再假设「字段一定齐全」：任何一条脏数据只影响它自己，不会让整卡失败。

## 4. 状态处理

| 状态 | 触发 | 卡片表现 |
|---|---|---|
| `loading` | 首次进入、无缓存数据 | 「读取中…」（标准）/ 脚注「读取中…」（紧凑） |
| `ready` + 有数据 | 正常返回 | 三块磁贴 + 最近 3 条 |
| `ready` + 空 | 返回空数组 / 全被丢弃 | 磁贴全 0 + 「暂无带截止日的待办」 |
| `error` | 桥报错 / 超时（8s）/ 缺权限 / 未检测到宿主 | 「读取失败：原因」+ **重试**按钮 |
| 静默刷新失败 | 已有数据时刷新失败 | 保留旧数据，不闪成错误页（下次成功自动恢复） |

错误文案已归一：`PERMISSION_DENIED` → 「缺少 data:read 权限」，超时 → 「读取超时」，
其它取 `message` 并截断 60 字。

重试按钮：`data-act="retry"`，点击会 `stopPropagation`，**不会**触发卡片跳转主视图。

未捕获异常（脚本错误、Promise rejection）也会渲染成错误态，不会停在「读取中…」。

---

## 5. 刷新策略

| 触发 | 行为 |
|---|---|
| 挂载 | 读配置 + 拉一次数据 |
| 60s 心跳 | 只重算 `nowMs` 并重绘（跨天换日） |
| 窗口重新可见 / 获得焦点 | 距上次成功加载 > 5s 时重新拉取 |
| 形态变化（`xhub:variant-changed`） | 仅切换排版，不重新请求 |
| 主题变化（`theme-changed`） | 重新测量卡面明暗，不重新请求 |

## 6. 如果要换成 HTTP 后端

当前契约只有一处入口：`module/data.js` 的 `fetchTodos()`。换成 REST 时改这里即可：

```js
// 原：宿主桥
const res = await api.data.todos.list();

// 改：HTTP（注意扩展页 CSP 的 connect-src 限制，需要宿主 network 权限或走 service 后端）
const r = await fetch('/api/todos');
const res = await r.json();
```

其余不用动：`normalizeTodo` 的字段兼容、`app.js` 的状态机、`countdown.js` 的计算、
样式与交互全部保持。字段名不一致时，在 `normalizeTodo` 里加别名即可
（例如后端用 `dueAt` 而不是 `due_at`，代码里已经同时接受两种写法）。
