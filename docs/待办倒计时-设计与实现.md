# 待办倒计时：设计与实现说明

> 目标程序：`x-hub 0.9.1 (win x64 portable)`
> 交付形态：x-hub 官方扩展（`com.zhou.todo-countdown`），只读待办数据，不改动可执行文件与数据库。

---

## 0. 先说明「为什么是扩展」

拿到的包只有两个文件：

```
portable          （空文件，便携模式标记）
x-hub.exe         11,263,488 字节
```

x-hub.exe 是 **Tauri 2 + Vue 3 + SQLite** 的编译产物：前端资源（`/assets/TodoView-*.js` 等 245 个）
以 **brotli 压缩块内嵌在二进制里**，资源偏移在编译期写死。这意味着：

- 没有源码，也无法把改过的 JS 重新塞回 exe（长度一变，偏移表和指针全错）；
- 即便做同长度字节补丁，也会被下一次升级覆盖，且无法审阅、无法测试。

而 x-hub 自带**官方扩展机制**：扩展是纯 HTML/JS 目录，宿主通过 `window.xhub` 桥把
`data.todos.*`（`data:read` / `data:write`）、`ui.notify`、`storage`、`config` 等能力开放给扩展。
这正是「给这个程序加功能」的受支持入口，因此本次实现为一个扩展：

| 需求 | 落点 |
|---|---|
| 剩余天数展示 | `view/`（分组列表）+ `module/`（工作台卡片） |
| 临期提醒 | `ui.notify` + 去重表（`xhub.storage`） |
| 状态区分 | 7 态状态机 + 5 档配色 |
| 界面更新 | 60s 心跳 + 跨天边界定时器 + 焦点兜底 |
| 边界情况 | 95 条断言的纯函数单测（3 个时区） |

### 0.1 逆向确认的事实基线（设计依据）

| 事实 | 证据 |
|---|---|
| `todos.due_at INTEGER`，毫秒时间戳，可空 | 内置 SQL：`due_at INTEGER`；类型注释「到期时间（毫秒时间戳）」 |
| 宿主已把 `due_at` 定义为「含当天」语义 | 桥接类型注释「截止日（毫秒时间戳，含当天）」 |
| 已有 `remind_at` / `remind_fired` | 建表语句；`todo_reminder.rs` 注释「remind_fired 防重复提醒」 |
| 已完成用 `done` + `completed_at`，子待办用 `parent_id`（级联删除） | 建表语句 |
| 周期待办用 `repeat_*`，完成时由宿主滚动 `due_at` | 桥接文档「周期规则只实现于宿主 Rust 侧，扩展不要自己算」 |
| 扩展可读待办 | 桥 `data.todos.list()`，需 `data:read` |
| 宿主对扩展**只广播** `theme-changed` / `xhub:variant-changed` | 桥接文档 `XHubEvents`；`todos-changed` 只在宿主内部使用 |

最后一条很关键：**扩展收不到待办变更事件**，所以刷新策略必须靠轮询 + 焦点 + 跨天定时器（见 §5）。

## 1. 数据结构与存储方式

### 1.1 数据源：宿主 SQLite（只读）

倒计时用到的字段（其余字段原样透传，不参与计算）：

| 字段 | 类型 | 语义 | 倒计时里的用途 |
|---|---|---|---|
| `id` | INTEGER PK | 待办 id | 行 key、提醒去重键 |
| `title` | TEXT | 标题 | 展示 |
| `done` | INTEGER 0/1 | 是否完成 | 完成项不参与倒计时与逾期统计 |
| `completed_at` | TEXT nullable | 完成时间 | 仅展示 |
| `due_at` | INTEGER nullable | **截止时刻，毫秒时间戳** | 全部天数计算的唯一输入 |
| `remind_at` | INTEGER nullable | 宿主提醒时刻 | 扩展不接管，避免与宿主双提醒 |
| `remind_fired` | INTEGER 0/1 | 宿主提醒是否已触发 | 同上 |
| `priority` | INTEGER 0/1/2 | 低/中/高 | 组内排序的次级键 |
| `parent_id` | INTEGER nullable | 父待办 | 子项折叠规则 |
| `repeat_mode` / `repeat_*` | TEXT/INTEGER | 周期规则 | 只打「周期」标，不推算 |
| `version` | INTEGER | 乐观锁版本 | 只读不使用 |
| `pinned` | INTEGER | 置顶 | 保留原样，不改变宿主排序语义 |

关键约定：

- **`due_at` 是毫秒，不是秒**。扩展侧 `parseDue()` 会校验范围（1970–2200、`<= 8.64e15`），
  非法值一律降级为「未排期」，绝不抛错、绝不显示 `NaN 天`。
- **不新增表、不新增列**。剩余天数是**派生值**：它随「今天」变化，一旦落库，
  跨天、改时区、夏令时都会立刻失真。宿主 `due_at` 已足够表达截止语义。
- **不写宿主数据**：本扩展只调用 `data.todos.list`，没有 `data:write` 权限。

### 1.2 扩展侧存储

| 存什么 | 存在哪 | 结构 | 生命周期 |
|---|---|---|---|
| 用户偏好 | `xhub.config` → 扩展目录 `.config.json` | 扁平 KV：`warnDays` / `dayStartHour` / `showCompleted` / `notifyEnabled` / `notifyCooldownHours` / `maxNotifyPerRun` | 升级扩展不丢；卸载即删 |
| 默认值 | `manifest.json` 的 `config` | 同上 | 随扩展包 |
| 提醒去重 | `xhub.storage`（扩展私有 KV） | `remindState = { "12:1762300800000:today": 1762311111000, ... }` | 超过 7 天的键在写入时清理 |
| UI 展开态 / 筛选 | 内存 + `sessionStorage`（仅提醒条关闭标记） | — | 关页面即失效 |

去重键格式：`${todoId}:${dueMs}:${status}`。

- 带上 `dueMs`：待办改了截止时间，就是新的一轮提醒；
- 带上 `status`：从「临期」走到「今天」应当各提醒一次，而不是被前一次吞掉；
- 值存**上次提醒的时间戳**，用于冷却窗口（默认 12h），而不是布尔值——布尔无法表达「隔天再提醒」。

## 2. 倒计时计算规则

### 2.1 核心定义：自然日差

```
业务日序号(ms) = floor( Date.UTC(本地年, 本地月, 本地日) / 86400000 )
d = 业务日序号(due_at) - 业务日序号(now)
```

- `d > 0`：还有 `d` 天
- `d = 0`：**今天到期**
- `d < 0`：已逾期 `-d` 天

**为什么不用 `(due - now) / 86400000`：**

| 场景 | 直接相除 | 自然日差 |
|---|---|---|
| 今天 23:00 截止，现在 09:00 | 0.58 天 → 四舍五入 1 天（错） | 0 → 今天 |
| 夏令时切换日（23h） | 差 0.958 天 → 舍成 0 天（错） | 1 天 |
| 夏令时回拨日（25h） | 差 1.04 天 → 舍成 1 天（碰巧对） | 1 天 |
| 跨时区旅行 | 依赖机器时区，容易偏一天 | 以当前本地日历为准，语义一致 |

做法是把「本地日历字段」重新拼成 UTC 零点再相减：日历日之间的差永远是整数天，
不受 23/25 小时的长度影响。

### 2.2 是否包含当天

**包含。** 明确定义两套口径，展示时分别使用：

| 口径 | 公式 | `d = 0`（今天） | 用途 |
|---|---|---|---|
| 日差 `d` | `dueDay - today` | `0` | 分组、排序、徽标数字 |
| 含当天剩余 `remainingInclusive` | `d + 1` | `1` | 悬浮提示「含当天还剩 N 天」、提醒文案 |

界面上「今天到期」不写「剩 0 天」，而是直接显示 **今天**；`d = 1` 显示 **明天**，
`d = 2` 显示 **后天**，其余显示数字，避免出现「剩 1 天 = 明天」的二次换算。

### 2.3 逾期如何显示

- 判定：`d < 0` 即逾期，显示 **`N 天` + 「已逾期」**，颜色取红色，排序最前。
- **当天已过具体时刻不算逾期**：`d = 0` 且 `now > due_at` 时，仍归入「今天」，
  但在徽标副文案标出 `18:00 已过`，视觉上仍是橙色而不是红色。

  理由：逾期是「错过了一整天」，而「今天 18:00 已过」只是当天的时点已过，
  把后者染成红色会让「今天到期」列表在下午集体变红，失去预警层次。
  需要严格到分钟的，宿主自己的 `remind_at` 提醒已经覆盖。

- 逾期不设上限：跨年也能算（`2026-12-31` → `2027-01-01` = 1 天，见测试）。

### 2.4 日界线 `dayStartHour`

默认 `0`（自然日）。可配成 `4`：凌晨 0–4 点仍算「昨天」。

```
业务日(03:30, 分界 4) = 昨天
业务日(05:00, 分界 4) = 今天
```

实现就是先减 `dayStartHour` 小时再取本地日历字段，因此「昨晚 23:00 的截止」
在凌晨 3 点看仍是「今天到期」，符合熬夜用户的直觉。

### 2.5 状态机（7 态）

| 状态 | 条件 | 分组标题 | 徽标 | 色 |
|---|---|---|---|---|
| `overdue` | `d < 0` | 已逾期 | `N 天` / 已逾期 | 红 |
| `today` | `d = 0` | 今天到期 | 今天 / `HH:mm 截止｜已过｜全天` | 橙 |
| `soon` | `1 ≤ d ≤ warnDays` | `N 天内`（默认 3 天内） | `N 天` / 明天·后天 | 琥珀 |
| `week` | `warnDays < d ≤ 7` | 一周内 | `N 天` | 蓝 |
| `later` | `d > 7` | 更远 | `N 天` | 灰 |
| `none` | `due_at` 缺失/非法 | 未排期 | 无徽标 | 灰 |
| `done` | `done = 1` | 已完成（默认折叠） | 完成 | 灰 |

`warnDays = 7` 时 `week` 自然为空；`warnDays = 0` 时 `soon` 为空——分档由阈值驱动，不是写死三段。

### 2.6 排序与分组

- 分组顺序固定：`已逾期 → 今天 → N 天内 → 一周内 → 更远 → 未排期 → 已完成`
  （先处理最痛的事，未排期放最后）。
- 组内排序：`days` 升序 → `priority` 降序 → 标题 `localeCompare('zh-Hans-CN')`。
- 统计口径：只统计**未被折叠**的条目；`done` 不计入逾期；
  `active`（页脚「N 项有截止日」）= 非 `done` 且非 `none`。

## 3. 展示、提醒与状态区分

### 3.1 主视图（`view/`）

```
┌ 待办倒计时   按截止日算剩余天数 · 逾期/今天/临期分色   [逾期 2][今天 3][临期 5] 阈值▾ 已完成☐ 刷新
├ 提醒条：2 项已逾期，3 项今天到期，建议优先处理。                                   ✕
├ 已逾期 2
│  ▌ 报销单提交（财务月结）        截止 10-29 18:00                     5天 / 已逾期
│  ▌ 给爸妈打电话                  截止 11-02 20:00                     1天 / 已逾期
├ 今天到期 3
│  ▌ 季度预算终稿提交              截止 11-03 18:00 含2个子项 高优先级   今天 / 18:00 已过
...
```

- 左侧 3px 色条 + 右侧数字徽标，颜色即状态，扫一眼就能分级；
- 元信息只保留「截止 11-03 18:00」与必要标签（周期 / 含 N 个子项 / 高优先级），
  相对时间交给徽标，避免同一句话出现两次；
- 点行展开描述（轻量 Markdown 降级为纯文本，截断 180 字），只读不改数据；
- 顶部三个胶囊即筛选器：点一下只看该分组，再点回到全部；
- 空态分四种：加载中（骨架）/ 读取失败（可重试）/ 没有任何待办 / 全部未排期。

### 3.2 工作台卡片（`module/`）

同一份 HTML，按 `data-xhub-variant` 切两套排版：

| 形态 | 尺寸（min / ideal） | 内容 |
|---|---|---|
| `compact` | 2×2 / 2×2 | 一个主数字（逾期优先 → 今天 → 临期）+ 一行「今天 3 · 临期 5」 |
| `standard` | 3×3 / 4×3 | 三块统计磁贴 + 最近 3 条（标题 + 状态天数） |

高度自适应：`container-type: size` + `cqh` 字号 + 容器查询，`max-height: 118px` 时收起脚注，
`max-height: 110px` 时标准形态隐藏列表只留磁贴。实测 5 种格子尺寸（180×86 ~ 420×186）均无溢出。

### 3.3 临期提醒

触发条件：状态 ∈ `{overdue, today, soon}` 且未完成。

```
候选 = 过滤(未折叠 && 状态命中 && 未完成)
     → 按紧迫度排序
     → 去掉冷却期内的（remindState[key] 距今 < notifyCooldownHours）
     → 取前 maxNotifyPerRun（默认 3）
     → xhub.ui.notify("待办倒计时 · 标题", "还有 2 天 · 截止 2026年11月6日 周五")
     → 写回 remindState
```

- **限流**：一次最多 3 条，避免开机瞬间弹一片；
- **冷却**：同一条同一阶段 12h 内只提醒一次，隔天会再提醒（值存时间戳而非布尔）；
- **降级**：`notify` 权限被拒 → 捕获 `PERMISSION_DENIED`，改为页面内提示条 + 「去开启」按钮
  （调 `xhub.openPermissions()`），不静默失败；
- **不与宿主打架**：宿主 `remind_at` 负责「精确到分」的提醒，本扩展只做「按天」的临期提醒，
  两者层次不同，不重复接管。

## 4. 界面更新逻辑

### 4.1 单向数据流

```
xhub.data.todos.list()
   → prepare()      合并子待办、标记 hidden/promoted、算 childCount
   → describe()     每条算 days / status / badge / caption
   → summarize()    统计
   → group()        分组 + 排序 + 过滤（warnDays、showCompleted）
   → render()       一次性重建分组 HTML
```

`render()` 是**幂等全量重绘**：以 500 条以内为设计目标，避免引入 diff 的复杂度与状态不同步。
重绘前记录 `scrollTop`，重绘后还原；展开态存在 `state.expanded[id]`，不随重绘丢失。

### 4.2 三条时间驱动

| 触发 | 频率 | 动作 | 解决什么 |
|---|---|---|---|
| 心跳 | 60s | 只更新 `nowMs` + 重绘 | 「今天」在 00:00 变「昨天」，徽标天数要跳 |
| 跨天边界定时器 | 每天一次 | `msUntilNextDayStart()` 精确定时到次日 `dayStartHour` + 1.5s，**重新拉数据**再重排定时器 | 熬夜/休眠后仍准确换日；数据也可能变了 |
| `visibilitychange` / `focus` | 事件 | 距上次加载 > 5s 则重新拉取 | 宿主里改了待办、切回窗口立刻同步 |
| 手动刷新 | 点击 | 清展开态 + 重新拉取 | 兜底 |

为什么不用事件：宿主对扩展只广播 `theme-changed` 和 `xhub:variant-changed`，
内部的 `todos-changed` 不跨 iframe。**轮询 + 焦点刷新**是当前 API 下唯一可靠的做法。

### 4.3 主题与形态联动

- 颜色全部走 `--xhub-*` 变量（`--xhub-surface` / `--xhub-text-1/2/3` / `--xhub-red|orange|yellow|blue`），
  深浅色各有一套兜底，因此宿主换主题、开壁纸、改强调色时页面自动跟随，不需要重绘；
- 卡片形态：`?xhub-variant=` 首帧 → 写入 `data-xhub-variant` → 监听 `xhub:variant-changed` 更新，
  三处统一落到 DOM 属性上，纯 CSS 分支才生效（宿主在拖拽换形态时不会重载 iframe）。

## 5. 边界情况处理

| # | 场景 | 行为 |
|---|---|---|
| 1 | `due_at = null` / 缺失 | 归「未排期」，无徽标，不进提醒 |
| 2 | `due_at = 0` / 负数 / `NaN` / 非数字字符串 / `> 8.64e15` / 年份越界 | `parseDue` 判非法 → 当作未排期，不抛错 |
| 3 | 截止时间正好 00:00 | 视为「纯日期」，文案「全天」，不显示时分 |
| 4 | 今天 23:59 截止 | 仍算今天（自然日口径），不会因为差 1 分钟被算成明天 |
| 5 | 今天 09:00 已过 | 仍归「今天」，副文案「09:00 已过」，不染红 |
| 6 | 逾期跨年 / 跨月 | 天数正确（`12-31 → 01-01 = 1`） |
| 7 | 闰年 2/29 | 天数正确（`02-28 → 02-29 = 1`） |
| 8 | 夏令时 23h / 25h 的一天 | 天数正确（`dayIndex` 用日历字段，不用毫秒除法） |
| 9 | 用户设了 `dayStartHour = 4` | 凌晨 0–4 点算前一天，昨晚 23:00 的截止显示「今天」 |
| 10 | 已完成但仍逾期 | 状态 `done`，**不计入逾期统计**，默认折叠 |
| 11 | 子待办，父级有截止日 | 折叠进父级，父项显示「含 N 个子项」，避免同一件事算两次 |
| 12 | 子待办，父级没有截止日 | **提升**为独立条目参与统计，否则它的截止日会被彻底忽略 |
| 13 | 子待办的 `parent_id` 指向不在列表里的父级 | 不隐藏（孤儿不丢） |
| 14 | 周期待办 | 用宿主给的 `due_at`（本轮时刻）+ 打「周期」标；**不自行推算下一轮**，避免与宿主两套算法打架 |
| 15 | 已完成 + 周期待办 | 同上，不参与逾期统计 |
| 16 | 通知权限被拒 / 桥报错 | 页面内提示条 + 「去开启」，不重复重试 |
| 17 | `storage` 不可用 | 内存兜底，仅影响提醒去重（可能同一天重复提醒一次） |
| 18 | 系统休眠 / 手动改系统时间 | 60s 心跳 + `focus` 重算；跨天定时器每次重排，不用累计计时 |
| 19 | 同时开主视图 + 工作台卡片 | 两个 iframe 各自轮询；提醒去重共用同一 storage 键，但**并发写有极小概率重复弹一次**（宿主未提供跨窗口锁，已知限制） |
| 20 | 超长列表（1000+） | 全量重绘会变慢；120 条实测流畅。设计目标 500 条内，更多建议用宿主自带列表 |
| 21 | 描述里有 Markdown / 代码块 | 降级为纯文本、去标记、截断 180 字，不注入 HTML |
| 22 | 标题含 `<script>` | 全部走 `esc()` 转义 |
| 23 | 深色 / 浅色 / 壁纸透底 | 全部用 `--xhub-*` 变量，双主题各有兜底；页面底用 `--xhub-page-bg`，不用 `--xhub-bg-page` |
| 24 | 卡片被拖到极矮格子（86px） | 容器查询收起次要信息，主数字保留，无裁切 |

## 7. 已知限制与后续可做

1. **不是宿主内置列表的一部分**：受限于编译产物，倒计时显示在独立视图与工作台卡片上；
   若你有源码，可直接合入 `TodoView`（见附录），数据层与 Rust 层无需改动。
2. **无跨窗口提醒锁**：多开时极端情况下可能重复弹一次通知。
3. **不接管 `remind_at`**：精确到分的提醒仍由宿主负责，本扩展只做日级提醒。
4. 可扩展方向：周起始日 / 工作日模式、农历与节日倒数、按标签筛选、把「剩余天数」写回 `description`、
   日历月视图（可用宿主 `expandOccurrences` 展开周期实例）。
